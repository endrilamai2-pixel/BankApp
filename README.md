# LoanEvaluationApp

[![Build](../../actions/workflows/build.yml/badge.svg)](../../actions/workflows/build.yml)

Εφαρμογή επιφάνειας εργασίας σε Java (Swing) για μια «τράπεζα»: εγγραφή πελατών με έλεγχο KYC, λογαριασμοί και μεταφορές,
αξιολόγηση αιτήσεων δανείου (ιδιώτες και επιχειρήσεις), λογιστική με διπλογραφία και διαχείριση κεφαλαίων.
Το περιβάλλον χρήστη είναι στα ελληνικά. Πρόκειται για εκπαιδευτικό project.

*English: a Java Swing desktop banking demo (customer registration with AADE KYC check, accounts and transfers, loan
assessment with credit scoring, double-entry ledger, capital allocation). The UI is in Greek. Educational project, not
for production use.*

## Λειτουργίες
- **Εγγραφή πελάτη** (ιδιώτες/επιχειρήσεις) με έλεγχο ΑΦΜ στην ΑΑΔΕ και παραγωγή IBAN
- **Πελάτες**: λίστα όλων των πελατών, αναζήτηση, κατάσταση KYC
- **Λογαριασμοί πελατών**: κατάθεση, ανάληψη, μεταφορά (με IBAN ή αριθμό λογαριασμού), δόσεις δανείων
- **Αξιολόγηση αίτησης δανείου**: credit score ιδιωτών, βαθμολόγηση επιχειρήσεων, εισαγωγή οικονομικών καταστάσεων
- **Λογιστική**: ισολογισμός, ισοζύγιο, ημερολόγιο
- **Διαχείριση κεφαλαίων**: βέλτιστη κατανομή ενεργητικού και επένδυση

## Απαιτήσεις
- Java 17 ή νεότερη
- Maven 3.8+ (για build/εκτέλεση)
- Microsoft SQL Server (π.χ. Express ή Docker)

## Εγκατάσταση και εκτέλεση

**1. Βάση δεδομένων.** Τρέξε το `sql/create-database.sql` (αφού αλλάξεις τον κωδικό μέσα του). Οι πίνακες δημιουργούνται
αυτόματα στην πρώτη εκκίνηση. Με Docker, για δοκιμές:
```bash
docker run -e ACCEPT_EULA=Y -e MSSQL_SA_PASSWORD='YourStrong!Passw0rd' -p 1433:1433 -d mcr.microsoft.com/mssql/server:2022-latest
```
και μετά τρέξε το `sql/create-database.sql` με το `sa`.

**2. Ρυθμίσεις.** Οι κωδικοί **δεν** βρίσκονται στον κώδικα· δίνονται με μεταβλητές περιβάλλοντος (ή `-D`, βλ. `.env.example`):

| Μεταβλητή | Ρόλος |
|---|---|
| `BANK_DB_PASSWORD` | **Υποχρεωτική.** Κωδικός του χρήστη της βάσης |
| `BANK_DB_USER` | Προαιρετική, προεπιλογή `bankuser` |
| `BANK_DB_URL` | Προαιρετική, προεπιλογή τοπικός SQL Server, βάση `BankDB` |
| `AADE_USERNAME`, `AADE_PASSWORD`, `AADE_CALLED_BY` | Προαιρετικές, πραγματικός έλεγχος KYC στην ΑΑΔΕ (αλλιώς δοκιμαστικά δεδομένα) |

**3. Εκτέλεση.**
```bash
export BANK_DB_PASSWORD='ο-κωδικός-σου'      # Windows (PowerShell): $env:BANK_DB_PASSWORD='...'
mvn compile exec:java
```
Στην πρώτη εκκίνηση η εφαρμογή ζητά να δημιουργηθεί ο πρώτος χρήστης. Από IDE: τρέξε την κλάση `LoanApp.LoanApp.Main`.

## Περιορισμοί
Εκπαιδευτικό project, όχι για παραγωγική χρήση: δεν υπάρχουν αυτοματοποιημένα τεστ, οι κανόνες δανεισμού, τα όρια και οι

## KYC μέσω ΑΑΔΕ
Κατά την εγγραφή πελάτη (ιδιώτη ή επιχείρησης) γίνεται έλεγχος του ΑΦΜ στην υπηρεσία RgWsPublic2 της ΑΑΔΕ:
το ΑΦΜ πρέπει να υπάρχει και να είναι ενεργό, ο τύπος (φυσικό/νομικό πρόσωπο) να ταιριάζει, και το όνομα/η επωνυμία
να συμφωνεί. Κάθε έλεγχος καταγράφεται στον πίνακα `kyc_checks`.
Αν ο έλεγχος δεν επαληθεύσει πλήρως τον πελάτη (ασυμφωνία, απόρριψη ή αδυναμία ελέγχου), ο υπάλληλος μπορεί να επιλέξει «Εγγραφή παρ' όλα αυτά»·
ο πελάτης εγγράφεται με εκκρεμή έλεγχο KYC και το πραγματικό αποτέλεσμα του ελέγχου καταγράφεται στο `kyc_checks` (με ένδειξη ότι έγινε εγγραφή).

Ρύθμιση (μεταβλητές περιβάλλοντος ή `-D`): `AADE_USERNAME`, `AADE_PASSWORD`, `AADE_CALLED_BY` (ΑΦΜ του φορέα),
προαιρετικά `AADE_ENDPOINT`. Χωρίς αυτά χρησιμοποιούνται δοκιμαστικά δεδομένα, που ΔΕΝ μετράνε ως έλεγχος KYC.
Ο πελάτης της ΑΑΔΕ δεν έχει δοκιμαστεί με την πραγματική υπηρεσία.

## Λογιστική (γενικό καθολικό)
Η τράπεζα τηρεί γενικό καθολικό με διπλογραφία (πακέτο `bank.ledger`). Κάθε κατάθεση, ανάληψη, εκταμίευση δανείου,
πληρωμή δόσης και μεταφορά μεταξύ διαφορετικών τύπων πελατών δημιουργεί αυτόματα ισοσκελισμένη εγγραφή, **μέσα στην
ίδια συναλλαγή βάσης** με την πράξη: ή αποθηκεύονται και τα δύο ή κανένα. Από το κεντρικό μενού, «Λογιστική»:
ισολογισμός (ενεργητικό / παθητικό και ίδια κεφάλαια), ισοζύγιο και ημερολόγιο, με έλεγχο ισοσκέλισης και συμφωνία
με τα υπόλοιπα των πελατών.

**Σημαντικό:** το σχέδιο λογαριασμών είναι **απεικονιστικό** και **δεν είναι το επίσημο Κλαδικό Λογιστικό Σχέδιο
Τραπεζών** (ΠΔ 384/1992). Ακολουθεί μόνο τη γενική διάρθρωση σε ομάδες (ενεργητικό στις ομάδες 1-3: πάγιο, χορηγήσεις,
απαιτήσεις/χρεόγραφα/διαθέσιμα). Οι κωδικοί των υπολογαριασμών είναι επιλογές του project (βλ. `ChartOfAccounts.java`).

Απλοποιήσεις: τόκοι σε ταμειακή βάση (χωρίς δουλευμένους τόκους), χωρίς αποσβέσεις, προβλέψεις ή αποτίμηση.
Για υπάρχουσα βάση: κουμπί «Αρχικά υπόλοιπα» καταχωρεί μία εγγραφή έναρξης από τα υπάρχοντα δεδομένα.

## Διαχείριση και επένδυση κεφαλαίων
Το πακέτο `bank.capitalInvestment` βρίσκει τη βέλτιστη κατανομή του ενεργητικού (δάνεια, ομόλογα, μετοχές, μετρητά)
υπό ρυθμιστικούς περιορισμούς (ελάχιστα αποθεματικά ΕΚΤ, LCR, κεφαλαιακή επάρκεια, μόχλευση, όριο κινδύνου).
Από το κεντρικό μενού, «Διαχείριση κεφαλαίων»:
- τα κεφάλαια (ενεργητικό και ίδια κεφάλαια) φορτώνονται από το γενικό καθολικό·
- «Επένδυση κεφαλαίων…» μετατρέπει διαθέσιμα μετρητά του ταμείου σε κρατικά ομόλογα, εταιρικά ομόλογα ή μετοχές.
  Το παράθυρο προτείνει αγορές με βάση το αποτέλεσμα του μοντέλου και δείχνει ποιοι περιορισμοί θα παραβιάζονταν·
- η επένδυση καταχωρείται στο καθολικό (χρέωση λογαριασμού χρεογράφων ομάδας 3, πίστωση ταμείου) σε μία συναλλαγή.

Απλοποιήσεις: οι αγορές γίνονται στην αξία κτήσης (χωρίς αποτίμηση ή πώληση), τα δάνεια ιδιωτών αντιστοιχούνται στην
κατηγορία «Καταναλωτικά» και των επιχειρήσεων στις «ΜμΕ». Οι αποδόσεις και οι κίνδυνοι είναι υποθέσεις, όχι προβλέψεις.

## Εμφάνιση και χρηστικότητα
Η εφαρμογή χρησιμοποιεί τη βιβλιοθήκη [FlatLaf](https://www.formdev.com/flatlaf/) για σύγχρονη εμφάνιση, αν υπάρχει
στο classpath. Αλλιώς δουλεύει κανονικά με το look του συστήματος (η φόρτωση γίνεται με reflection στο `bank.ui.Theme`).

- **Με Maven:** `mvn compile exec:java` (το `pom.xml` φέρνει FlatLaf, οδηγό SQL Server και PDFBox).
- **Χωρίς Maven:** κατέβασε το `flatlaf-*.jar` και πρόσθεσέ το στις βιβλιοθήκες του IDE.

Κεντρικό μενού με κάρτες και συντομεύσεις (πλήκτρα 1–6)· φόρμα εγγραφής με υποδείξεις στα πεδία, ΑΦΜ μόνο με ψηφία
και άμεσο έλεγχο ορθότητας, επισήμανση των πεδίων με λάθος, Enter για επόμενο πεδίο και αντιγραφή IBAN· σύνδεση με
εμφάνιση κωδικού και προειδοποίηση Caps Lock· πίνακες με εναλλασσόμενες γραμμές.

## Λίστα πελατών
Από το κεντρικό μενού, «Πελάτες» (πακέτο `bank.customers`): λίστα όλων των ιδιωτών και επιχειρήσεων, μόνο για ανάγνωση.
Στον πίνακα φαίνονται μόνο τα βασικά στοιχεία (όνομα/επωνυμία, ΑΦΜ, IBAN, υπόλοιπο, ενεργά δάνεια, κατάσταση KYC, ημερομηνία
εγγραφής)· τα πλήρη στοιχεία ανοίγουν με διπλό κλικ ή Enter. Υπάρχει αναζήτηση με όνομα, ΑΦΜ ή IBAN, φίλτρο τύπου
και φίλτρο «Μόνο με εκκρεμές KYC». Η κατάσταση KYC προκύπτει από τον τελευταίο έλεγχο του ΑΦΜ στον πίνακα `kyc_checks`
(Επαληθευμένος / Εκκρεμής / Απορρίφθηκε – εγγράφηκε / Χωρίς έλεγχο). Η λίστα φορτώνεται ολόκληρη, χωρίς σελιδοποίηση.

## Αριθμός λογαριασμού, ημερομηνίες, τηλέφωνο
- **Αριθμός λογαριασμού** = τα 10 τελευταία ψηφία του IBAN. Στη μεταφορά (Λογαριασμοί πελατών) το πεδίο προορισμού δέχεται
  είτε ολόκληρο IBAN είτε αριθμό λογαριασμού. Ο αριθμός λογαριασμού φαίνεται στα στοιχεία λογαριασμού, στη λίστα πελατών και
  μετά την εγγραφή. Επειδή ο τύπος πελάτη (ιδιώτης/επιχείρηση) βρίσκεται στα ψηφία πριν από τα τελευταία 10, ένας ιδιώτης και μια
  επιχείρηση με το ίδιο id έχουν ίδιο αριθμό λογαριασμού· τότε η εφαρμογή ζητά να επιλέξει ο υπάλληλος τον σωστό δικαιούχο.
  Πριν την εκτέλεση εμφανίζεται πάντα το όνομα του δικαιούχου για επιβεβαίωση.
- **Ημερομηνίες** (ΗΗ/ΜΜ/ΕΕΕΕ): οι κάθετοι μπαίνουν αυτόματα· δέχεται μόνο ψηφία, και επικόλληση (`12051990` ή `12/05/1990`).
- **Τηλέφωνο**: μόνο ψηφία, μέχρι 10· στην εγγραφή απαιτούνται ακριβώς 10 ψηφία.
